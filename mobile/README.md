# Мобильное приложение (Expo + expo-router)

Каркас приложения заново: Expo SDK 57, экраны файлами через **expo-router**,
интерфейс на готовой библиотеке **React Native Paper** (Material 3).
Данные — тот же Supabase, что и раньше (`../supabase`).

## Запуск

```bash
cd mobile
npm install
cp .env.example .env   # заполнить EXPO_PUBLIC_SUPABASE_URL и EXPO_PUBLIC_SUPABASE_ANON_KEY
npx expo start
```

Значения для `.env` — в Supabase Dashboard → Project Settings → API. После
`git pull` один раз выполните `npx expo install --check`, чтобы сверить версии
нативных пакетов с SDK (из среды разработки нет доступа к `api.expo.dev`).

## Структура

Экраны лежат в `src/app` — путь файла и есть адрес экрана:

- `_layout.tsx` — корень: Paper, React Query, сессия. Через `Stack.Protected`
  решает, какие группы экранов доступны: без входа — только `login`,
  админу/диспетчеру — `(office)`, водителю/грузчику — `(employee)`. Вошедшему
  без строки в `employees` (роль не назначена) показывается экран «нет
  доступа» вместо какого-либо экрана приложения — см. раздел «Роли и права» ниже.
- `index.tsx` — перенаправляет на нужный стартовый экран по роли.
- `login.tsx` — вход (общий для всех ролей); поле «Логин» принимает как
  обычный email, так и короткий логин без `@` (см. «Роли и права»).
- `(office)/` — общие вкладки админа и диспетчера: `calendar` (режимы 1, 3 и
  7 дней; листается бесконечно и всегда останавливается на границе страницы;
  при входе открывается на красной линии текущего времени; заказ окрашен в
  цвет своей услуги, закончившийся — в серый; фильтр по сотруднику, «+» и тап
  по слоту — скрыты без права «создавать заказы»),
  `clients` (поиск, телефон, персональная скидка, заметки, история заказов
  клиента; «Добавить» сразу открывает контакты телефона и подставляет имя и
  номер; телефон и история скрыты без соответствующих прав), `team` —
  «Команда», только для админа: список всех логинов с ролью и созданием/правкой
  через `AccountDialog`, и `stats` — «Статистика», тоже только для админа:
  сводка по компании (число заказов по статусам, выручка по завершённым) и
  по каждому сотруднику (`api/stats.ts`, всё время, без фильтра по датам),
  `fleet` — «Автопарк», список машин с созданием/правкой/удалением
  (`VehicleDialog`), и `schedule` — «График»: диспетчер выбирает сотрудника
  чипом и ставит ему выходные на календаре месяца (без права «создавать
  заказы» — только просмотр). `fleet` и `schedule` видны и админу, и
  диспетчеру (в отличие от `team`/`stats` — только админ).
- `(employee)/my-orders.tsx` — тот же календарь, но только заказы сотрудника;
  в шапке добавлена кнопка «Мой график» → `my-schedule.tsx`.
- `my-schedule.tsx` — самообслуживание графика для водителя/грузчика
  (модальный экран, тот же календарь, что и в «Графике» у диспетчера):
  редактировать может только тот, кому на аккаунте включили
  `can_manage_own_schedule`, иначе только просмотр. Отдельный файл, а не
  `(office)/schedule.tsx` — тот доступен только админу/диспетчеру и правит
  чужой график; этот — сотруднику свой (см. «Автопарк и рабочий график» ниже).
- `order/[id].tsx` — карточка заказа, права зависят от роли (см. «Роли и
  права» ниже): админ/диспетчер меняют статус и любое поле, могут удалить
  заказ; водитель без полного управления правит только время и сумму
  (отдельный блок «Изменить время и сумму»), остальное только смотрит;
  грузчик только смотрит и суммы не видит никогда. Сотрудник при открытии
  отмечается как «открыл заказ», может нажать «Принять заказ» и позвонить
  клиенту — это не зависит от прав на редактирование. Доп. точки маршрута
  свёрнуты под «Ещё точки»; кнопка «Маршрут в Яндекс.Картах» строит маршрут
  по всем точкам. Гос номер назначенной машины показан компактной строкой
  под именем водителя; если водитель на этом заказе же и грузчик — в списке
  экипажа одна строка «Водитель и грузчик», а не два человека.
- `order/new.tsx` — создание заказа (без права «создавать заказы» — экран
  сразу показывает «Недостаточно прав»): клиент обязателен (поиск или новый
  из контактов телефона),
  услуги из каталога (задают длительность и подставляют сумму), 2 основные +
  доп. точки маршрута, груз, водитель и грузчики, сумма вручную. Дата и
  время — пикеры `react-native-paper-dates`. Водитель и грузчики — с точкой
  доступности у имени (зелёная свободен, жёлтая занят другим заказом,
  красная выходной; занятый грузчик недоступен для выбора, занятый водитель
  доступен — см. «Автопарк и рабочий график»); выбор водителя подставляет
  его машину по умолчанию (можно сменить) и добавляет его же в список
  грузчиков как напарника (можно убрать).

Остальное в `src/`:

- `api/` — запросы к Supabase на React Query, включая `accounts.ts` (список
  аккаунтов, создание через Edge Function, смена роли/прав), `stats.ts`
  (сводка для экрана «Статистика» — считается на клиенте одним запросом,
  как `useClientOrderStats`), `vehicles.ts` (автопарк) и `schedule.ts`
  (выходные дни: `useEmployeeDaysOff` для календаря сотрудника,
  `useDaysOffOn` для точки доступности в форме заказа).
- `components/calendar/` — календарь: `PagedCalendar` (листание страницами),
  `DayCells` (шапка дня, колонка, линия времени), `OrderBlock` (блок заказа).
- `components/form/` — поле даты/времени, секция формы и выбор услуг.
- `components/accounts/AccountDialog.tsx` — создание и правка аккаунта
  (роль, логин/пароль при создании, четыре переключателя прав, машина по
  умолчанию для водителя).
- `components/vehicles/VehicleDialog.tsx` — создание/правка/удаление машины.
- `components/schedule/DayOffCalendar.tsx` — календарь месяца с выходными
  (общий для «Графика» диспетчера и `my-schedule.tsx`); `canEdit` решает,
  можно ли тапом ставить/снимать выходной, или только смотреть.
- `providers/SessionProvider.tsx` — сессия и `employee` (строка `employees`
  вошедшего, откуда берутся роль и права — см. «Роли и права» ниже).
- `lib/permissions.ts` — проверки прав по роли и переключателям (см. «Роли и
  права» ниже); у админа всегда полный доступ.
- `lib/accountLogin.ts` — превращение логина в email для Supabase Auth.
- `lib/` — клиент Supabase и push-уведомления.
- `theme.ts` — тема Paper, цвета статусов заказа, подписи/иконки ролей.

## Роли и права доступа

Четыре роли входа — `employees.role`: `admin` (администратор/владелец),
`dispatcher` (диспетчер), `driver` (водитель), `loader` (грузчик). У
диспетчера, водителя и грузчика — независимые переключатели на аккаунте (у
админа всегда включены и в интерфейсе не показываются как переключаемые):
«создавать/редактировать/удалять заказы» (`can_manage_orders`), «смотреть
историю и статистику по клиентам» (`can_view_client_stats`), «видеть
контакты и суммы заказов» (`can_view_contacts_and_amounts`) — и, только у
водителя и грузчика, «может сам ставить себе выходные»
(`can_manage_own_schedule`, выключен по умолчанию — см. «Автопарк и рабочий
график» ниже).

Права — это роль + переключатели поверх неё (`lib/permissions.ts`): у
каждой роли свой набор действий по умолчанию, а переключатели администратор
может донастроить на конкретном аккаунте (`AccountDialog`, значения по
умолчанию зависят от выбранной роли):

- **Диспетчер** — по умолчанию видит и правит всё; переключатели могут это
  сузить (как и раньше).
- **Водитель** — по умолчанию видит все поля заказа и календаря, но правит
  только время начала/окончания и сумму (отдельный блок на карточке
  заказа, а не полное редактирование); статус, экипаж и остальные поля —
  только смотрит. Переключатель «создавать/редактировать/удалять заказы»
  выдаёт водителю то же самое, что диспетчеру (тогда узкое право на
  время/сумму уже не нужно — оно и так внутри полного). Переключатель
  «видеть контакты и суммы» решает, видит ли он телефон клиента и сумму
  (по умолчанию — да, «видит все поля»).
- **Грузчик** — всегда только смотрит заказ, каким бы ни был переключатель
  «создавать/редактировать/удалять заказы» (устроено так же, как у
  водителя, но самой кнопки редактирования у грузчика нет). Сумму заказа не
  видит никогда, ни при каком переключателе. Телефон клиента видит, если в
  бригаде этого заказа нет водителя (тогда общаться с клиентом приходится
  ему самому) — либо всегда, если включить переключатель «видеть контакты
  и суммы» (тогда сумма всё равно останется скрытой).
- **Администратор** — как диспетчер, плюс вкладки «Команда» (заводит и
  удаляет аккаунты, назначает роль и переключатели) и «Статистика» (по
  компании и по каждому сотруднику).

Только администратор видит вкладки «Команда» и «Статистика», и может
заводить остальных —
там же задаются логин, пароль и права. Логин — не email: экран входа
принимает короткую строку (латиница/цифры/`._-`) и сам превращает её во
внутренний адрес `<логин>@mdtrans.internal` для Supabase Auth (если ввести
обычный email с `@` — используется как есть, так входит администратор,
заведённый напрямую в Supabase). Создание аккаунта с паролем идёт через
Edge Function `create-account` (`../supabase/functions/create-account`),
потому что установить пароль можно только через Admin API с service role
key, которому нельзя оказаться в мобильном приложении — см.
`../supabase/README.md`.

Права на создание/правку/удаление заказов проверяются и в Postgres (RLS +
сами RPC, миграция `0005_roles_and_permissions.sql`), а не только в
интерфейсе. Узкое право водителя (только время/сумма) — тоже в Postgres:
триггер запрещает менять остальные колонки заказа, если нет полного
управления (миграция `0006_fixed_role_permissions.sql`, см.
`../supabase/README.md`). Видимость телефона клиента и суммы заказа —
только в интерфейсе.

## Автопарк и рабочий график

**Автопарк** («Автопарк» в нижних вкладках, видна админу и диспетчеру) —
список машин компании (`VehicleDialog`: название и гос номер обязательны,
остальное — грузоподъёмность, размеры кузова, европаллеты, три
чек-поинта — опционально). Заводить/менять/удалять машину может тот же,
у кого есть право «создавать/редактировать/удалять заказы» — отдельного
переключателя под автопарк нет. У каждого водителя есть машина по
умолчанию (выбирается в «Команде», поле «Авто по умолчанию» появляется
только при роли «Водитель»); в форме нового заказа она подставляется
автоматически при выборе водителя, но диспетчер может выбрать другую —
машина закрепляется один раз при создании, экрана «сменить машину на уже
созданном заказе» нет.

**Рабочий график** («График» в нижних вкладках у диспетчера/админа —
правит любого сотрудника; «Мой график» кнопкой в шапке у водителя/грузчика
— только свой, и только если включено «может сам ставить себе выходные»,
иначе только просмотр). Режим выбирает сам сотрудник на «Моём графике»
(«Отмечаю выходные» — по умолчанию все дни рабочие, отмечаете нерабочие;
«Отмечаю рабочие» — по умолчанию недоступен, отмечаете, когда готовы
работать; проще для подрабатывающих). Смена режима не трогает уже
проставленные дни — у каждой отметки свой явный статус, режим решает
только дни без отметки. Нажатие на день открывает диалог: рабочий или
выходной, и опционально часы («по часам» вместо «весь день») — сужают
рабочий день до конкретного окна. Там же — «Копировать» (переносит
отметку выбранного дня на другие, можно вставить на несколько дней подряд)
и «Перенести» (то же самое, но исходный день после этого сбрасывается).
Диспетчер на «Графике» видит режим сотрудника, но меняет только сам
сотрудник. Выходной (и часы) — это подсказка при назначении бригады, не
жёсткий запрет: заказ всё равно можно создать, приложение только не
выделит этого человека зелёной точкой.

**Доступность в форме заказа** — у каждого водителя/грузчика при выборе
даты и времени точка у имени: зелёная — свободен, жёлтая — уже назначен на
другой заказ в это время, красная — выходной или не в рабочие часы (тогда
рядом подпись с часами, например «работает 09:00–14:00»); список
сортируется в этом же порядке (свободные сверху). Красная точка — это
только подсказка, выбрать такого человека всё равно можно: диспетчер
знает ситуацию лучше приложения. Жёлтая точка (другой заказ) устроена
по-разному: грузчика с ней выбрать нельзя (в базе это и так запрещено —
назначение отклонится), а водителя можно — с 0007 разрешено вести два и
более заказа одновременно («сборный груз» — одна машина, несколько грузов
рейсом). Водитель, выбранный на заказ, по умолчанию добавляется и в
список грузчиков как собственный напарник (частый случай — небольшой
заказ, где водитель сам же и грузит); диспетчер может убрать его оттуда
отдельной галочкой, не снимая с заказа как водителя.

**Перенос и копирование заказа** — на карточке заказа диспетчер/админ
(даже не будучи в бригаде — раньше блок был виден только бригаде) видит
«Изменить время и сумму»: правка даты/времени и есть перенос заказа.
Кнопка «Копировать заказ» открывает форму нового заказа, предзаполненную
данными этого — клиент, маршрут, груз, экипаж, машина, услуги, сумма и то
же время; дату проверяете и меняете сами перед сохранением.

## Push-уведомления

Логика та же, что в старой версии (`src/lib/pushNotifications.ts`): экран
сотрудника регистрирует push-токен, создание заказа шлёт уведомление экипажу.
Для реальной доставки нужен EAS project ID: `npx eas init` локально.
