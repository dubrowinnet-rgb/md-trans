# МД Транс — CRM для грузоперевозок

Мобильное приложение + веб-кабинет + бэкенд для компаний-перевозчиков
(админ/диспетчер, водители, грузчики). Смоделировано по образцу Bumpix.
Полное ТЗ — `TZ_prilozhenie_gruzoperevozki.md` в корне репозитория.

## Структура репозитория

- `mobile/` — мобильное приложение (Expo + expo-router). Основной клиент
  и для админа/диспетчера, и для экипажа (водители/грузчики).
- `supabase/` — вся схема БД, миграции и Edge Functions. Общие для
  мобильного и веб-кабинета — одна база на оба приложения.
- `deploy/selfhost/` — установка и обновление на собственном сервере
  (152-ФЗ: данные остаются в России — основной способ хостинга).
- `web/` — веб-кабинет диспетчера/админа (Next.js + Mantine). Живёт на
  отдельной ветке `claude/project-thread-8z4luq` (свой PR) — в этом
  чекауте (`claude/project-thread-cbnmzl`) его нет.

## Ветки и кто где работает

Каждая область разрабатывается в своём треде проекта, в своей ветке:
- мобильное + вся схема/бэкенд (этот репозиторий) — `claude/project-thread-cbnmzl`, PR #1.
- веб-кабинет — `claude/project-thread-8z4luq`, PR #2 (нацелен на PR #1,
  после его слияния — на `main`).
- сборка APK, пуш-уведомления, сервер — отдельные build-треды и ветки, см.
  `deploy/selfhost/README.md`.

**Миграции и бэкенд пишет только мобильный тред** — веб-кабинет вручную
копирует уже готовые миграции и часть кода (`src/types/database.ts`,
`src/lib/*.ts`, часть `src/api/*`), своих миграций не заводит.

## Мобильное приложение (`mobile/`)

Expo SDK 57, expo-router, React Native Paper, TanStack Query поверх
`@supabase/supabase-js`. **Перед тем как писать код по Expo/expo-router —
прочитайте `mobile/AGENTS.md`**: версия API меняется быстрее, чем знания
модели, точные версионные доки обязательны.

Маршруты (`mobile/src/app/`):
- `(office)/` — админ/диспетчер: календарь, клиенты, автопарк, график,
  статистика, команда.
- `(employee)/` — водитель/грузчик: свои заказы.
- `order/new`, `order/[id]` — общие для обеих ролей (конкретные права
  проверяются внутри экрана, а не на уровне маршрута).
- `settings/` — свой вложенный стек: профиль, услуги, шаблоны смс,
  напоминания, отчёты водителей, обращения в поддержку и т.д.

Остальное: `api/` — хуки react-query, обычно по одному файлу на
сущность; `lib/` — чистая логика без UI (телефоны, права, смс,
услуги); `components/` — переиспользуемые диалоги и виджеты; `hooks/` —
сквозные React-хуки (например `useRealtimeSync`); `providers/SessionProvider`
— сессия и текущий сотрудник; `types/database.ts` — вручную
поддерживаемые типы схемы (держать в синхроне с миграциями).

## База данных и бэкенд (`supabase/`)

- `migrations/NNNN_*.sql` — строго по возрастающим номерам, **каждая
  безопасно перезапускаема** (`if not exists` / `drop ... if exists`
  везде) — так заведено с первых миграций и ожидается от новых.
  Нумерация сквозная для мобильного и веба (веб ничего своего не
  добавляет).
- `functions/` — Edge Functions на service role (создание/правка
  аккаунта, увольнение, пуши, уведомления о заявках в поддержку и т.д.)
  — нужны, когда операцию нельзя выполнить с anon-ключа (например работа
  с Supabase Auth).
- Мультиарендность: почти у каждой таблицы `company_id` + RLS
  (`get_my_company_id()` / `is_admin()`), заведено в миграции 0013.
  Повторяющийся идиом проверки прав админа/диспетчера — инлайновая
  проверка через `exists (select 1 from employees where auth_user_id =
  auth.uid() and role in ('admin','dispatcher') and company_id = ...)`, а
  не отдельная функция (`is_admin()` проверяет только role='admin').
- Подробный ручной план накатки на облачный Supabase и объяснение выбора
  «свой сервер vs облако» — `supabase/README.md`.

## Развёртывание (`deploy/selfhost/`)

Собственный сервер в РФ — основной способ (152-ФЗ). `update.sh` тянет
`claude/project-thread-cbnmzl` (бэкенд/миграции/функции) и отдельно
веб-ветку (`web_branch` в конфиге, по умолчанию
`claude/project-thread-8z4luq`) — при изменениях в обеих областях нужно
запушить в обе ветки, не только в одну. Подробности, резервное
копирование, восстановление — `deploy/selfhost/README.md`.

## Общие соглашения

- Код и комментарии — на русском (продукт для русскоязычного заказчика);
  комментарии объясняют **почему**, а не что делает код.
- Телефоны везде в формате `+7(xxx)xxx-xx-xx` (`lib/phone.ts` — одна и
  та же логика в обоих приложениях).
- Смс клиентам не уходят с сервера — приложение открывает системный
  экран отправки смс, текст набран заранее, отправляет сам диспетчер.
- Коммиты и PR не должны упоминать конкретную модель ИИ — это только для
  чата.
