# Свой сервер в России

Всё, что сейчас работает в Supabase Cloud (за рубежом), ставится на один
ваш сервер в российском дата-центре: база данных, вход по телефону, фото,
функции (создание сотрудников, пуши, напоминания), веб-кабинет и HTTPS.
Данные сотрудников и клиентов хранятся только на нём — так требует
152-ФЗ (ст. 18, ч. 5).

Внутри — официальная сборка Supabase для своего сервера (self-hosted,
версия закреплена в `lib.sh`), поэтому приложения и кабинет работают с ней
так же, как с облаком.

## Что понадобится

- **Сервер (VPS)** в российском дата-центре: Timeweb Cloud, Selectel,
  REG.RU или другой. Система **Ubuntu 24.04**, 4 ядра, 8 ГБ памяти, диск
  80 ГБ (минимум — 2 ядра, 4 ГБ, 40 ГБ). Сразу включите у хостинга
  автоматические резервные копии сервера — это платная опция, но только
  она спасёт, если сломается сам сервер.
- **Домен**, например `mdtrans.ru` (можно и `.рф`). В его DNS-записях —
  три записи типа A на IP сервера: `@`, `www` и `api`.
- **Пароль root** от сервера — его присылает хостинг. Никому не пересылайте.

## Установка

1. На компьютере с Windows нажмите «Пуск», введите `PowerShell` и откройте
   его. Подключитесь к серверу — вместо `IP` IP-адрес вашего сервера:

   ```
   ssh root@IP
   ```

   На вопрос `yes/no` ответьте `yes`, затем введите пароль root (при
   вводе он не виден — это нормально).

2. Вставьте по одной строке, после каждой нажмите Enter:

   ```
   curl -fsSL https://raw.githubusercontent.com/dubrowinnet-rgb/md-trans/refs/heads/claude/project-thread-cbnmzl/deploy/selfhost/install.sh -o install.sh
   ```

   ```
   bash install.sh
   ```

3. Установщик спросит:
   - домен (например, `mdtrans.ru`);
   - название компании — так её увидят в приложении;
   - ваше имя и номер телефона — это вход администратора;
   - пароль администратора (дважды, при вводе не виден);
   - пароль владельца сервиса — отдельный вход в кабинет, где видны все
     компании-клиенты (Enter — такой же, как у администратора).

   Дальше всё идёт само, обычно 15–30 минут. Окно не закрывайте.

4. В конце установщик напишет:
   - **адрес сервера** `https://api.<домен>` и **публичный ключ** (anon
     key). Это не секреты — пришлите их Claude в проект, по ним он соберёт
     приложение для телефонов;
   - адрес веб-кабинета `https://<домен>`: вход по вашему телефону и
     паролю;
   - как войти владельцу сервиса: на том же сайте «Войти по логину или
     email», логин `owner`.

Если установка прервалась (закрылось окно, пропал интернет) — подключитесь
снова и запустите `bash install.sh` ещё раз: повторный запуск безопасен,
уже созданные входы он не пересоздаёт.

Если в конце написано, что HTTPS пока не работает, — DNS-записи домена ещё
не дошли до сервера. Подождите: как только записи заработают, сертификат
выпустится сам, ничего запускать не нужно.

## Обновление

Когда Claude пишет, что вышла новая версия сервера или кабинета, —
подключитесь к серверу (`ssh root@IP`) и выполните одну строку:

```
bash /opt/md-trans/repo/deploy/selfhost/update.sh
```

Сначала делается резервная копия, потом скачивается новая версия,
накатываются изменения базы, обновляются функции и веб-кабинет. Обычно
5–10 минут, приложения и сайт всё это время работают.

Новые версии приложения для телефонов обновлять не нужно: сервер раз в час
сам проверяет, не собрана ли новая, и выкладывает её на страницу установки
`https://<домен>/install/`.

## Резервные копии

- Каждую ночь (в 00:30 по часам сервера) сервер сохраняет базу, фото и
  свои ключи в `/opt/md-trans/backups`. База и ключи хранятся 14 дней, фото — 7.
- Сделать копию прямо сейчас:

  ```
  bash /opt/md-trans/repo/deploy/selfhost/backup.sh
  ```

- Эти копии лежат на том же сервере, поэтому автоматические копии у
  хостинга всё равно нужны.
- Восстановить данные из копии (например, если что-то удалили по ошибке) —
  напишите Claude, он даст точные команды; технические шаги ниже.

## Панель базы данных (Studio)

Для работы она не нужна, поэтому из интернета закрыта. Если понадобится
заглянуть в базу, на своём компьютере в PowerShell:

```
ssh -L 8000:127.0.0.1:8000 root@IP
```

Пока это окно открыто, панель открывается в браузере по адресу
`http://localhost:8000`. Логин — `supabase`, пароль покажет команда на
сервере (в том же окне):

```
grep DASHBOARD_PASSWORD /opt/md-trans/supabase/.env
```

## Что где лежит на сервере

| Путь | Что там |
|---|---|
| `/opt/md-trans/supabase` | Supabase в Docker; `.env` — все пароли и ключи сервера |
| `/opt/md-trans/repo` | копия этого репозитория: миграции, функции, эти скрипты |
| `/opt/md-trans/web-repo` | копия ветки веб-кабинета, пока он в отдельной ветке |
| `/opt/md-trans/backups` | ночные резервные копии |
| `/opt/md-trans/config` | домен и ветки, выбранные при установке |

Файл `.env` и резервные копии никому не пересылайте и не вставляйте в чат:
по ним можно получить доступ ко всем данным.

## Как устроена защита

- Снаружи открыты только SSH (22) и HTTPS (80/443). База, панель Studio,
  пул соединений и шлюз API слушают только внутри сервера.
- Через `api.<домен>` доступны только адреса, которыми пользуются
  приложения и кабинет (`/auth`, `/rest`, `/storage`, `/functions`,
  `/realtime`). Функции, которые вызывает только сама база (напоминания,
  пуши об изменениях, уведомление о новом обращении), снаружи закрыты.
- Самостоятельная регистрация выключена: входы заводит администратор.
  Подбор пароля ограничен: после ~30 неудачных попыток с одного адреса
  сервер временно отвечает отказом. SSH защищает fail2ban.
- Пуши идут через Expo, Apple и Google (за рубежом), поэтому в их тексте
  нет адресов, имён и телефонов — только общие фразы, дата и время заказа.

## Для Claude: технические детали

**Что делает установщик.** `install.sh` скачивает этот репозиторий в
`/opt/md-trans/repo` и продолжает оттуда. Ставит Docker (официальный
репозиторий, запасной вариант — пакеты Ubuntu), ротацию логов, swap 2 ГБ,
fail2ban; если Docker Hub недоступен, включает зеркала
(`dockerhub.timeweb.cloud`, `mirror.gcr.io`). Официальный `setup.sh`
Supabase с тега `SUPABASE_RELEASE` раскладывает сборку в
`/opt/md-trans/supabase` и генерирует секреты (вывод маскируется).
`apply_config` (`lib.sh`) правит `.env` (домены, вход по телефону без
подтверждения, `DISABLE_SIGNUP`, `FUNCTIONS_VERIFY_JWT=false`, без
OpenAI), кладёт наш `Caddyfile` вместо официального и подключает
`docker-compose.mdtrans.yml` (шлюз только на 127.0.0.1, пул соединений
без портов, лимит входов по `X-Forwarded-For` — его выставляет Caddy,
подделать нельзя). Функции копируются в `volumes/functions` (роутер `main`
официальный, `hello` удаляется). Миграции идут по порядку, каждая в одной
транзакции; выполненные записываются в `private.applied_migrations`. После
миграций `private.app_settings.functions_base_url` =
`http://functions:9000` — по нему pg_cron и триггеры (миграция 0018)
вызывают функции мимо внешнего адреса. Первая компания — из миграции 0013
(`00000000-0000-0000-0000-000000000001`), администратор и владелец
заводятся через Admin API GoTrue (телефон администратора в E.164, email
`<цифры>@mdtrans.internal`; у владельца `owner@mdtrans.internal`).
Веб-кабинет ставит `deploy/web/setup-web.sh` из ветки кабинета
(`web_branch` в `/opt/md-trans/config`), его Caddyfile подключает наш через
`import /etc/caddy/Caddyfile`. cron: `/etc/cron.d/md-trans-backup`
(00:30 по часам сервера) и `/etc/cron.d/md-trans-app` (каждый час).

**Приложение на странице установки.** После сборки в EAS обновите
`deploy/app-release.json` (формат — в `publish_app_files`, `lib.sh`) и
запушьте. `publish-app.sh` раз в час читает этот файл с GitHub (raw, код
сервера не трогает), скачивает APK в
`volumes/proxy/mdtrans/files/md-trans.apk` (проверяет `sha256`, если он
указан) и пишет `files/install.json` в формате
`web/src/lib/installInfo.ts`. Если скачать не удалось — на странице будет
прямая ссылка на Expo, следующая попытка через час.

**Откат базы из копии** (проверено на тестовой копии):

```
cd /opt/md-trans/supabase
docker compose stop caddy api-gw auth rest storage realtime functions studio meta supavisor imgproxy
docker exec -i supabase-db pg_restore -U supabase_admin -d postgres --clean --if-exists < /opt/md-trans/backups/db_<время>.dump
sh run.sh start
```

Ожидаемые ошибки — только `cannot drop inherited constraint
"messages_…_pkey"` (служебные разделы realtime), на данные они не влияют.
Фото той же ночи: отложите текущую папку (`mv volumes/storage
volumes/storage.old`) и распакуйте `tar -xzf
/opt/md-trans/backups/storage_<время>.tar.gz -C volumes` до `sh run.sh
start`. Перед откатом сделайте свежую копию (`backup.sh`).

**Проверка скриптов на тестовой машине.** Пути и ответы задаются
переменными: `MDTRANS_BASE` (вместо `/opt/md-trans`), `MDTRANS_REPO`,
`MDTRANS_USE_LOCAL_REPO=1` (не скачивать репозиторий),
`MDTRANS_SKIP_SYSTEM=1` (не трогать apt, Docker, swap, cron),
`MDTRANS_SKIP_WEB=1`, `MDTRANS_DOMAIN=mdtrans.localhost`,
`MDTRANS_COMPANY`, `MDTRANS_ADMIN_NAME`, `MDTRANS_ADMIN_PHONE`,
`MDTRANS_ADMIN_PASSWORD`, `MDTRANS_OWNER_PASSWORD`. `*.localhost` Caddy
обслуживает своим сертификатом (`curl -k`). В песочнице Claude, где
исходящий HTTPS идёт через прокси со своим сертификатом, контейнеру
`functions` нужен этот сертификат (смонтировать поверх
`/etc/ssl/certs/ca-certificates.crt`, `DENO_TLS_CA_STORE=system`), сборке
кабинета — `WEB_BUILD_DOCKER_OPTS` с `NODE_EXTRA_CA_CERTS`, а `supavisor` —
`RLIMIT_NOFILE` поменьше. Всё это — отдельный локальный override, не в
репозитории.

**Версия Supabase** обновляется только вручную: поменять
`SUPABASE_RELEASE` в `lib.sh`, проверить все миграции и функции на
тестовой копии, отдельно продумать перенос `.env` и `docker-compose.yml`
на сервере (`update.sh` сам этого не делает).
