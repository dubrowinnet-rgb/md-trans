# Веб-кабинет на своём сервере

Кабинет — это готовые файлы (HTML/JS), своего сервера ему не нужно. На
сервере с self-hosted Supabase его отдаёт тот же Caddy, что и API:

| Адрес | Что там |
|---|---|
| `https://<домен>` | веб-кабинет (этот каталог) |
| `https://www.<домен>` | перенаправляет на `https://<домен>` |
| `https://<домен>/files/…` | файлы для скачивания, например APK приложения |
| `https://api.<домен>` | API Supabase и Studio (официальный `docker-compose.caddy.yml`) |

HTTPS-сертификаты Caddy получает и продлевает сам (Let's Encrypt). Нужно
только, чтобы DNS-записи `@`, `www` и `api` домена указывали на IP сервера.

## Установка и обновление

Одна команда, повторять можно сколько угодно — это и есть обновление:

```sh
sh deploy/web/setup-web.sh /путь/к/проекту/supabase
```

Скрипт:

1. Берёт из `.env` проекта Supabase адрес API (`SUPABASE_PUBLIC_URL`),
   публичный ключ (`ANON_KEY`) и домен (`WEB_DOMAIN`, по умолчанию
   `PROXY_DOMAIN` без `api.`).
2. Собирает `web/` в контейнере `node:22-alpine` — ставить Node на сервер
   не нужно. Сборке нужно ~1,5 ГБ памяти; если на сервере меньше 8 ГБ и
   нет подкачки, скрипт сам добавит `/swapfile` на 2 ГБ.
3. Кладёт сборку в `volumes/proxy/mdtrans/www/releases/<время>` и
   переключает ссылку `current` — сайт обновляется без простоя, три
   последние сборки остаются на месте.
4. Копирует `Caddyfile` и `docker-compose.mdtrans-web.yml` в проект
   Supabase и включает их после официального Caddy
   (`sh run.sh config add caddy mdtrans-web`).
5. Если Caddy уже запущен и его настройки изменились — пересоздаёт его
   (несколько секунд). Если не запущен — он стартует с остальным стеком
   (`sh run.sh start`).

Если сборка не удалась, на сайте остаётся предыдущая версия.

## Что где лежит в проекте Supabase

```
docker-compose.mdtrans-web.yml   дополняет сервис caddy
volumes/proxy/mdtrans/
  Caddyfile                      подключает официальный + сайт кабинета
  www/current -> releases/…      то, что сейчас на сайте
  www/releases/…                 последние сборки
  files/                         APK и другие файлы для /files/
```

Официальные файлы Supabase не меняются, поэтому их `update.sh` обновляет
без конфликтов.

## Проверено

Официальный Supabase `self-hosted/v0.8.2` (Postgres 17, Envoy) + все
миграции 0001–0017 + этот каталог, с адресами `mdtrans.localhost` /
`api.mdtrans.localhost`:

- вход по телефону;
- все разделы кабинета;
- создание сотрудника через Edge Function `create-account` и его вход;
- заголовки кэша и безопасности, ошибок CSP в консоли нет;
- страница 404, перенаправления `/путь` → `/путь/` и `www` → без `www`;
- Studio закрыт паролем;
- повторный запуск: новая сборка без перезапуска Caddy.
